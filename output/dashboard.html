    How a run works

    1. 06:30, Windows Task Scheduler wakes the PC and starts scripts/run_daily.ps1.
    2. Checks (Python). Every input file is validated, then 17 business checks run across flow, tracker against installation records, compliance and supplier invoices. The same data always gives the same result.
    3. Review (Claude, headless). Classifies every exception by cause and owner, sets priority, writes the report and drafts chase emails. It can read files and write to output/ only, with no shell access.
    4. Validation (Python). The classification must cover every exception exactly once, using fixed cause and owner lists, or the run is retried and then marked failed.
    5. Dashboard. This page is rebuilt. A person decides the open questions and sends the drafts they approve.

    Controls

    • Nothing is sent automatically. Every email is a draft.
    • Source data and rules are never changed.
    • Nothing is marked resolved. An exception closes when the data is fixed and the next run stops finding it.
    • A failed run never shows green: broken input turns the banner red, an incomplete run amber.
