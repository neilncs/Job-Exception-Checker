Solar Job ExceptionsDaily reconciliation of jobs, installs, invoices and compliance documents. Synthetic sample data.

Open exceptions over time

Target: trending towards zero. Each point is one daily run (from output/run_log.csv).

How this works

  1. 06:30 - Windows Task Scheduler wakes the PC and starts scripts/run_daily.ps1.
  2. Deterministic checks (Python) validate every input file (data-quality check X1), then run 17 business checks across flow, tracker vs install, compliance and supplier invoices. Same data in, same answer out.
  3. Claude (headless) reads the evidence, groups exceptions by root cause, names an owner, sets priority, writes the report and drafts chase emails. Its permissions only allow reading files and writing to output/, with no shell access: the runner runs the checks itself.
  4. This dashboard is rebuilt. A person reviews it, decides the Needs human review items and sends the drafts they approve.

What it never does

  • Send an email or message
  • Edit the source data or the rules
  • Mark anything resolved: an exception closes only when the data is fixed and the next run stops finding it

When something goes wrong

  • Broken input (missing file/column, bad rules): run stops, says why, run log untouched.
  • Bad rows (invalid date, duplicate ID): reported as data-quality exceptions and quarantined so they can't cause false alarms.
  • Claude step fails or stalls: each attempt is stopped after 15 minutes and retried up to 3 times; if all fail, the facts are still here and the banner says so.
